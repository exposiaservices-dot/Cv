# دليل الوكيل لتصميم محفظة

1. اقرأ `PORTFOLIO_TEMPLATE_SPEC.md` والمهارة `.agents/skills/portfolio-template-design/SKILL.md`. افهم الهدف والجمهور واللغة والاتجاه والهوية البصرية والخصوصية، واسأل عن المعلومات المؤثرة والمواد المصرح بها. لا تختلق أسماء أو أدوارًا أو مؤهلات أو عملاء أو نتائج أو أرقامًا أو روابط؛ اترك الناقص فارغًا.
2. عدّل المحتوى وترتيب الأقسام وظهورها وإعدادات المظهر والخطوط في `src/data/portfolio/index.ts` أولًا. استخدم المكونات المسجلة؛ لا تعِد بناء محرك العرض أو تعدّل المكونات المشتركة لمجرد ملء البيانات. إذا طلب المستخدم تصميمًا لا يستوعبه العقد، أضف لبنة عامة موثقة ومختبرة بأقل تغيير.
3. افحص ملكية الصور والمشاريع والروابط والإذن بنشرها، وتجنب الأسرار والبيانات الخاصة. لا تستخدم صورًا أو محتوى من المختبر على أنه حقيقة. حدّث بيانات الصفحة الوصفية والأيقونة عند حصولك على بيانات معتمدة، مع مراعاة `BASE_PATH`.
4. تجنّب فصل حروف العربية، وراعِ RTL والتباين وfocus ومقاسات الشاشات وتقليل الحركة. اجعل المشاهد الثقيلة كسولة وWebGL اختياريًا. راجع `docs/PORTFOLIO_LIBRARIES.md` و`docs/PROJECT_LIBRARIES.md` قبل إضافة اعتماد وحدّث الفهرس عند الحاجة.
5. استدعِ `validatePortfolio` ببيانات العمل، وراجع حالة الفراغ/النقص/الاكتمال. لا تحوّل تعريف الاكتمال التقني إلى ادعاء نشر أو حقيقة. شغّل `npm ci` و`npm run check` وافحص الموقع بصريًا وباللمس ولوحة المفاتيح وRTL وتقليل الحركة، واذكر ما لم يُختبر. حافظ على اختبارات الفراغ باستخدام نسخة فارغة إذا عُبّئت بيانات الإنتاج.
6. عدّل `.ruler/rules/` ثم شغّل `npm run ai:rules` عند تغيير تعليمات الوكلاء؛ لا تحرر الملفات المولدة يدويًا. لا تنشر أو تدفع أو تغيّر الخصوصية دون إذن صريح. اطلب قرار استضافة خاصة وضمان التحكم في الوصول قبل نشر أي محتوى.

للعرض الأصلي فقط استعمل `?mode=presentation` واقرأ أدلة العرض والمذكرات. لا تفرض ترتيب الشرائح أو شروط الأطروحة على المحفظة.
