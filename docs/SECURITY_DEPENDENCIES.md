# مراجعة أمن الاعتمادات

## النتيجة

في 2026-11-03، أظهر `npm audit` قبل الإصلاح **45 تنبيهًا**: 11 متوسطًا و29 عاليًا و5 حرجة. كانت النتيجة نفسها عند فحص نسخة مستقلة من ملف القفل للمصدر. بعد التعديلات أدناه أظهر الفحص **صفر تنبيهات** في ذلك التاريخ. هذه لقطة لقاعدة بيانات npm، وليست ضمانًا بعدم وجود ثغرات: قد تظهر تنبيهات جديدة، ولا تفحص الأداة كل شيفرة أو أصل أو طريقة استخدام أو ملف JavaScript مضمّن داخل حزمة.

## ما عُولج

1. **Vitest**: تحديث أداة الاختبار من 3.2.7 إلى 5.1.0، بما يزيل التنبيهات المرتبطة بـ`vitest` و`@vitest/mocker` و`tinypool` في نتيجة الفحص. يدعم الإصدار Node `^22.12.0 || ^24.0.0 || >=26.0.0`؛ لذلك أُعلن هذا الشرط في `package.json`، وأُضيفت أنواع Node صراحةً إلى إعداد TypeScript. راجع مثلًا [تنبيه Vitest](https://github.com/advisories/GHSA-82fw-gwwq-j7x9) و[تنبيه Tinypool](https://github.com/advisories/GHSA-85c8-ppgw-ccpr).
2. **إضافة الشرائح**: حزمة `reveal.js-plugins@4.6.0` المنشورة كانت تُدرج `npm@6` كاعتماد، ومنه تأتي شجرة قديمة تحتوي على تنبيهات، منها `request` و`form-data` و`tar`. لم نجد استيرادًا لـnpm في ملفات الإضافة أو سكربتات في manifest تحتاجه؛ تطبيقنا يستعمل أصلًا تنفيذاته المحلية للسبورة وغيرها، وليس استيرادًا مباشرًا للإضافة.
3. للحفاظ على الإضافة نفسها وملفاتها وترخيصها، نُسخت **الحزمة الرسمية المنشورة نفسها** إلى `vendor/reveal.js-plugins/`؛ التغيير الوحيد فيها هو إزالة اعتماد npm من `package.json`. باقي الملفات مطابقة للحزمة الأصلية. تفاصيل المصدر وبصمة الحزمة والترخيص في [vendor/README.md](../vendor/README.md). هذا تعديل محلي على manifest وليس إصدارًا رسميًا جديدًا. إزالة الاعتماد القديم لا تثبت أمن شيفرة الإضافة أو الملفات المضمنة فيها.
4. أُضيف `npm run check:vendor` لفحص قائمة الملفات وبصمات SHA-256 للنسخة المحلية ضمن `npm run check`. هذا يحمي من تغيير غير مقصود مقارنةً بالmanifest المحلي، لكنه ليس توقيعًا مستقلًا إذا عُدّل الملفان معًا. عند تحديث الإضافة، قارنها بالحزمة الرسمية وتحقق من ترخيصها ثم حدّث البصمات عن قصد.

لم تُستخدم `npm audit fix --force`، ولم يُحذف محرك الشرائح أو اختبارات المشروع. اختلف ملف القفل بسبب ترقية أدوات الاختبار وإزالة شجرة npm القديمة؛ أصل إضافة المحاكاة GitHub وcommit الخاص بها لم يتغيرا.

## إعادة الفحص

```bash
npm ci
npm run check          # يشمل فهرس المكتبات وسلامة النسخة المحلية والأنواع والاختبارات والبناء
npm audit              # كل اعتمادات ملف القفل
npm audit --omit=dev   # دون أدوات التطوير
```

تُشغّل CI فحص `npm audit --audit-level=high` على طلبات السحب أو يدويًا؛ يمكن أن يفشل لاحقًا عند صدور تنبيه جديد، حتى إن لم تتغير الشيفرة. لا تستخدم بيانات أو أصولًا غير مصرح بها، ولا تنشر موقعًا قبل مراجعة الخصوصية والتراخيص وأمن الاستضافة أيضًا.
