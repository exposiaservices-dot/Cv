# مكتبات المحفظة — خريطة عملية

المشروع يحتفظ بمكتبات المصدر ومكوناته كما هي. لا يعني تثبيت مكتبة أنها تُحمّل في الصفحة الرئيسية أو أنه يجب استخدامها في كل محفظة. القائمة الكاملة وفحص تطابقها مع `package.json` في [PROJECT_LIBRARIES.md](PROJECT_LIBRARIES.md). بيانات المحفظة تبقى فارغة افتراضيًا؛ لا تنسخ بيانات المختبر إلى الإنتاج.

| --- | --- | --- |

## فحص بيانات غير موثوقة

النوع TypeScript وحده لا يفحص JSON وقت التشغيل. استخدم المخطط عند إدخال بيانات من ملف أو واجهة خارجية؛ ارفض المدخل غير المطابق قبل تمريره إلى مكون `Portfolio`:

```ts
import { portfolioDataSchema } from '@/portfolio/schema';
import { validatePortfolio } from '@/portfolio/validate';

export function inspectPortfolio(input: unknown) {
  const parsed = portfolioDataSchema.safeParse(input);
  if (!parsed.success) return { ok: false as const };
  return { ok: true as const, data: parsed.data, validation: validatePortfolio(parsed.data) };
}
```

المخطط لا يملأ القيم، ويرفض الحقول الزائدة أو أنواع البيانات الخاطئة. `validatePortfolio` يتحقق من الشكل أيضًا ويعيد `partial` مع مسارات تبدأ بـ`schema.` عند فشل الشكل، دون تضمين قيم المدخلات. بعد اجتياز الشكل، `blank` صالح و`partial` يشير للنقص أو الروابط غير الصالحة و`complete` يعني اجتياز الحد الأدنى فقط. أسماء المسارات قد تكشف بنية البيانات؛ تعامل مع سجلات الأخطاء وفق سياسة الخصوصية. `isPortfolioBlank` مخصص للبيانات المطابقة لنوع `PortfolioData`، وليس لفحص مدخل مجهول مباشرة.

هذا لا يفحص ملكية الروابط أو أذونات النشر، ولا يمنع المخاطر المترتبة على تحميل صور أو روابط خارجية موثوقة ظاهريًا. افحص الأصول والخصوصية على حدة. لا تنشر الملفات الخام أو الأخطاء التي تحوي بيانات شخصية.

## الجودة والأداء

- استخدم المكتبات الموجودة أولًا؛ لا تضف اعتمادًا بلا حاجة فعلية واختبار وترخيص وتحديث للفهرس.
- لا تحمّل 3D أو الرسوم الثقيلة أو تأثيرات الخلفية في الصفحة الأساسية ما لم تطلبها الحاجة؛ استخدم `lazy` وبدائل مناسبة.
- اختبر لوحة المفاتيح واللمس وRTL والتباين وتقليل الحركة؛ لا تفترض أن مكتبة أو مغلّفًا يضمن ذلك تلقائيًا.
- حافظ على اختبارات القالب الفارغ واختبارات المدخل غير الصحيح، وشغّل `npm run check` قبل التسليم.

## مراجعة أمن الاعتمادات

عولجت تنبيهات الفحص التي ظهرت في نسخة المصدر؛ التفاصيل والمقارنة وحدود الفحص في [SECURITY_DEPENDENCIES.md](SECURITY_DEPENDENCIES.md). أعد تشغيل `npm audit` دوريًا، لأن قاعدة التنبيهات تتغير، ولا تعامل نتيجة خالية من التنبيهات كضمان أمني شامل.
